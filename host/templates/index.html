Using pico-bdm

Typical order: Connect → Sync target (the chip identifies itself automatically) → Program, debug, or read/write memory. Watch the Log panel for what actually happened.

The Features menu
Only the four panels you need for connect-and-flash are on the page: Connection, Chip, Program and Log. Everything else — the live debugger, the package pin view, the memory map, security, verify/dump and the raw memory/register/scope tools — opens from Features in the header, as a slide-over you can dismiss with Esc, the x, or a click outside it. Opening and closing a panel never stops anything: live polling and a running programming job are global and keep going whether their panel is on screen or not.
Connection
Pick your Pico's serial port (Refresh if it's missing) and click Connect. Once connected, click Sync target to power-cycle the target into background mode and measure its BDC clock — do this before any read, write, or program. Relink is the other recovery: it re-measures the bit rate and re-asserts ENBDM without resetting the target, so a program that is running keeps running. Use Relink when the live panel says the link was lost; use Sync when you want to start from a known reset.
Chip
Fills in automatically after Sync. The part ID (SDID) only identifies the family — the SG8 and SG4 share one ID — so the derivative is settled by probing whether RAM exists at $0240, which is why it says "probed" rather than "id-only". Deep probe additionally scans $0060–$006F for silicon-defective RAM cells on this particular die and runs the FLASH module's own blank check.
Program
Set the target's bus clock in Hz and pick an erase mode: erase only the pages you're about to write (default), mass-erase the whole chip first, or skip erasing entirely. Programming is page at a time: erase → program → verify one 512-byte page before the next is touched, so a failure names the page and address it stopped at and every page before it is confirmed good. The memory map animates each page as the target confirms it — nothing is drawn ahead of the hardware. Verify reads the same file back off the chip independently of programming. Dump reads the FLASH array to a timestamped .s19 under host/backups/.
Live state & debugger
Polls the target a few times a second. Two honesty rules are enforced: CPU registers are shown as unavailable whenever the CPU is running (BDCSCR.BDMACT=0) because the register is changing under the read, and a link that stops answering is shown as LINK LOST rather than rendered as 0xFF data. Halt is the BDC BACKGROUND command, Step is TRACE1, and Set BKPT writes the breakpoint address and arms it (BDCSCR.BKPTEN=1) — arming matters, because BDCSCR resets with BKPTEN=0.
Memory map
The target's whole address space. Colours are region type until you press Scan, which reads the chip and recolours each cell by what is actually in it (blank 0xFF vs. programmed). Defective RAM cells are marked from a live scan of this die, never from a hardcoded table — the defect on this board has measurably spread between sessions.
Security
Lock chip programs NVOPT to set the SEC bits; after the next reset the part refuses all FLASH/RAM access over BDM. Unsecure & wipe is the forgot-passcode recovery: it mass-erases and then runs the FLASH blank check, because on HCS08 a mass erase alone does not release security — the erase-verify does. Both take an automatic backup first (server side, into host/backups/), and both require typing a confirmation word.
Chip package & live pins
The 20-TSSOP package drawn to its real pinout (data sheet Table 2-1), with each port pin lit from the same /api/live_state poll the debugger uses — bright = driven/read high, dim = low, outlined = configured as an input. Hover a pin for its number, port bit, alternate functions and live direction/level; click to pin that card open. Only three target pins are wired to the programmer (RESET, BKGD and VDD), so a real waveform can be captured on BKGD directly; any other pin needs a jumper to a spare Pico GPIO, and the card says so rather than drawing a trace it cannot measure.
Memory / Registers / Scope (Features → Advanced)
Byte-level peek and poke, direct register access, and the self-capture scope that draws the actual BKGD waveform without a separate logic analyzer.
Log
Running history of every command sent and its result, newest at the bottom. Clear wipes it.
