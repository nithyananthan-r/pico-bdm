pico-bdm

background debug controller — S08/RS08

Using pico-bdm

Typical order: Connect → Sync target → Program or read/write memory. Watch the Log panel for what actually happened.

Connection
Pick your Pico's serial port (Refresh if it's missing) and click Connect. Once connected, click Sync target to measure the target chip's BDC clock — do this before any read, write, or program. Reset target is a plain RESET pulse (target reboots and runs its own code); Go resumes execution from BDM.
Flash
Set the target's bus clock in Hz and pick an erase mode: erase only the pages you're about to write (default), mass-erase the whole chip first, or skip erasing entirely. In "touched pages" mode every page the file touches is erased once, up front — never per-region, because two regions of a real .s19 routinely share a 512-byte page and erasing per-region would wipe an already-programmed region. Choose a compiled .s19/.srec file and click Program. Every region is read back and verified by the Pico itself before it reports success, so there is no verify option to turn off. Run target after programming resumes the target's own code once flashing finishes. Blank check asks the FLASH module itself whether the chip is erased. The standalone Mass erase button wipes the whole chip's FLASH on its own — irreversible, used rarely.
Memory (under "Show advanced")
Read or write a single byte/block at a given address once synced — useful for peeking at registers or poking test values by hand.
Registers & breakpoint (under "Show advanced")
Read/write the CPU's A, CCR, PC, H:X and SP registers directly. Set BKPT writes the BDC breakpoint address and arms it (BDCSCR.BKPTEN=1, force mode) — arming matters, because BDCSCR resets with BKPTEN=0 and the breakpoint register does nothing at all while it's clear. Once armed, resume with Go and the target halts back into BDM when it reaches that address. Tagged GO is not a "run to breakpoint" button: HCS08 parts have no external tag-input pin (HCS08RMv1 §7.3.4.16), so TAGGO behaves exactly like a plain GO here — it's exposed only for completeness. Step single-steps one instruction (TRACE1). BDCSCR is the BDC's own status/control register; Read it first (Write stays disabled until you have, because writing the default 0x00 would clear CLKSW and break the bit timing Sync just calibrated).
Scope (under "Show advanced")
Self-capture diagnostic panel that draws the actual BKGD waveform without needing a separate logic analyzer. A second, passive PIO state machine watches the line while the selected operation runs, triggered by the line's first falling edge so Python's imprecise call timing doesn't matter. Enabled and proven on real hardware as of 2026-09-12 — it is what found the protocol bugs recorded in CONTEXT.md. Note that the same Pico both drives and records, so it cannot catch a fault in its own clock; and only the first 128 samples of a fast capture are guaranteed contiguous in time (the PIO RX FIFO is 4 words deep). The raw capture serial command also accepts window_us to zoom out to a whole transaction, and a "command" test to capture an arbitrary BDC command — both well worth using directly, see README.
Options
Log display preferences (auto-scroll, timestamps) and the sample count Scope will use once it's re-enabled. Erase and run-after-program options live directly in the Flash panel.
Log
Running history of every command sent and its result, newest at the bottom. Clear wipes it.
